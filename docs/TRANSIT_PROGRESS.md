# 0.0.84：系统中转进度与打开耗时

独立运行新增居中进度卡片，显示“正在解冻”和“正在打开”。本体被冻结时，卡片由系统侧原生窗口显示，不启动本体 Activity，也不解冻本体。普通模式保留原来的桥接页面。

升级后重启设备，保持本体解冻，等待系统重新确认配置，再冻结本体。卡片沿用同步的主题色与明暗偏好；选择跟随系统时，按系统当前日夜模式取色。卡片仅用于模块实际接管的事务，正常网页、无匹配规则或未接管的已启用目标不会出现提示。

## 显示与关闭

- 确定唯一且可解冻的目标后显示“正在解冻”；状态回读确认可用后进入“正在打开”。已启用目标被允许接管时直接显示打开阶段。
- 提交启动请求不代表窗口已绘制。卡片等目标窗口绘制或已绘制窗口恢复后关闭，没有人为等待快链路的最短显示时间。
- 热重用关联新投递的 Intent；多级路由丢失额外标记时，按同包、同用户、打开阶段和事件时间关联目标实际窗口。
- 老事务的绘制、超时和失败不能关闭更新的卡片。权限弹窗只中断进度提示，不当作目标内容页打开成功。
- 卡片不抢焦点，不接收触摸，不铺全屏遮罩。切用户、锁屏、Home／最近任务、失败及 12 秒超时会收起；后端不会等待卡片或动画。
- 支付 SDK 原始调用链继续直通，不额外插入卡片、等待或结果回放。

明暗卡片使用同一颜色种子；文字、摘要、主题操作色对卡片与内层底色按至少 4.5:1 校验。配置保持 schema 8／codec 1，旧存储缺少新主题字段时使用蓝色与跟随系统，保留全部规则、在线缓存和版本高水位。

## 分段日志

`transit timing` 每笔事务使用独立 id，记录以下阶段：

- `worker-start`：工作线程开始。
- `thawing`：开始修改目标状态。
- `opening`：状态可用，准备调用启动接口。
- `submitted`：启动接口成功返回。
- `window-ready`：目标窗口绘制或已有可见窗口恢复。
- `system-prompt`：出现系统权限窗口，仅收起提示，不表示目标已完成。

`elapsedMs` 从捕获开始计算；`sourceStartMs` 记录原请求继续执行到入队的时间；`queueMs` 记录入队等待；`workerMs` 从工作线程开始计算；`thawMs` 为解冻到打开阶段的时长。没有发生的阶段用未测值表示，不伪造零耗时。日志只包含事务 id、用户、包名和时长，不写原 URL、剪贴板或 SDK 参数。

“窗口可见”仍不同于网页数据加载完成：应用自己的启动页、权限、登录和网络加载需要由目标应用完成。

## 验证边界

回归包括阶段顺序、重复和失败不误报、观察器异常不影响后端、新旧事务隔离、冷绘制标记更新顺序、无标记多级路由、热重用、权限提示、日夜配色与原生窗口焦点／触摸。

debug 的非导出预览 Activity 使用 Activity 子窗口，复用相同卡片布局与显示状态；它验证原生渲染，不等同于真实 system_server 的系统窗口权限。生产使用 system_server classloader 获取 UiThread，以及 TYPE_SYSTEM_DIALOG；Android 12 起同时设置 trusted overlay。API 36 独立 app_process 未登记为 AMS 应用进程，不能代替系统窗口验收；当前模拟器平台证书也不匹配公开 AOSP 开发平台证书，因此未尝试安装系统 UID 宿主或修改系统权限。

输入回归等待真实焦点、布局和输入事务后注入点击，并确认背景收到 DOWN 和点击回调。测试需要访问 `UiAutomation.syncInputTransactions()` 测试接口，可以仅对 instrumentation 进程执行：

```powershell
adb -s emulator-5556 shell am instrument --no-hidden-api-checks -w -r io.github.yudigaga.icebridge.test/androidx.test.runner.AndroidJUnitRunner
```

该参数不修改设备全局隐藏 API 策略，也不用于正式应用。

用户手机上的实际系统窗口、前台权限提示和首帧回调仍需安装后验证。最终构建与设备结果见 [RELEASE_VALIDATION.md](RELEASE_VALIDATION.md)。原始日志、数据库及本地采样不提交仓库。
